# When the work gets an issue

How a skill decides whether to open a GitHub issue. Pointed at, never copied.

- **Open one** for a piece that needs a plan on GitHub: a feature, a conversion,
  a multi-phase refactor, work still owed after this PR.
- **Skip** a package update, and a quick maintenance fix (a one-phase cleanup, a
  small bugfix, a tidy).
- **completionism** - open one only for a very large piece that spans several
  PRs. Everything else, including a multi-phase change that ships as one PR,
  skips.
- An issue that already exists is still used.
