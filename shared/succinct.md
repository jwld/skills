# Succinct

How a skill keeps its chat messages to the user short. Pointed at, never
copied. Text written for GitHub (a PR description, an issue, a comment) follows
its own skill instead.

The user reads every chat message mid-task, so each one carries only what their
next decision or action turns on.

- Lead with the outcome: the verdict, the result, or the question.
- Give an item the fewest lines the user can act on: usually one, its name and
  the fact that matters.
- Name what the user already saw this session rather than explaining it again.
  An agreed finding is its title, not its case.
- Leave out what came out fine, what was checked to get there, and how the work
  went.
- Leave out a list with nothing in it, rather than heading it over "none".
- Gather the offers at the end into one question, as [choices.md](choices.md)
  sets out.
- Draft, then cut each sentence the user's next decision doesn't turn on. Cut
  whole sentences, and keep the ones left complete.
